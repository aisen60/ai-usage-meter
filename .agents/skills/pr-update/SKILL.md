# PR Update

更新一个已存在、仍处于开放（`state=open`，含 `isDraft=true` 的草稿）状态的 GitHub Pull Request。以执行时的 Git、GitHub CLI 与开发者确认作为唯一事实来源；不要凭对话概述猜测变更、PR 状态或提交范围，也不要缓存 PR 数据。

## 交互顺序

遵循以下顺序。每次仅提出一个尚未解决的关键问题。

1. 首次面向开发者的提问必须是：`PR 标题和摘要要使用什么语言？`
2. 定位目标 PR：优先当前分支关联的 PR；开发者也可提供 PR 编号或 URL。候选不唯一或指定目标无法读取时，停止并请求开发者选择或修正，不得猜测。
3. 询问目标状态：保持现状、转为可合并的 `open`，还是转为 `draft`。
4. 询问是否要在 `CHANGELOG.md` 记录本次修改。
5. 完成只读预检和差异分析，生成完整草案。
6. 将完整草案发给开发者审核。开发者要求修改时只更新草案并重新审核。
7. 只有开发者明确批准完整草案后，才执行 Changelog 写入、Git 提交、推送和 PR 编辑。

PR 标题与摘要使用开发者在第 1 步选择的语言。`CHANGELOG.md` 新增内容始终使用中文。Git commit 的人类可读信息默认使用中文，遵循 `$git-commit` skill。

## 目标 PR 定位

- 默认以当前分支关联的 PR 为目标；也可按开发者给出的 PR 编号或 URL 定位。
- 仅允许操作 `state=open` 的 PR。草稿 PR 以 `isDraft=true` 表示，同样可操作。
- 关闭或已合并的 PR 只报告其状态，不修改、不重开、不合并、不关闭。
- 仅修改 PR 标题、正文或状态时，可操作通过编号或 URL 指定的另一分支 PR。
- 若草案包含本地 Changelog、提交或推送，当前分支必须与目标 PR 的 head 分支一致；不一致时停止，不自动切换分支。

## 只读预检

在生成草案前，检查以下状态：

- `gh` 已安装且 `gh auth status` 成功；当前远端对应 GitHub 仓库。
- 目标 PR 唯一且可读取，其 `state=open` 与 `isDraft` 状态清晰。
- 通过 `gh pr view` 或 `gh pr list` 读取目标 PR 的标题、正文、head 分支和状态，不凭记忆推断。
- 仅当草案包含本地 Changelog、提交或推送时，再验证：当前 HEAD 不游离、当前分支与目标 PR 的 head 分支一致、工作区与新增差异已读取。

若 `gh` 不可用或未认证、远端不是 GitHub、目标 PR 无法读取或不唯一、PR 已关闭或已合并，停止并报告原因。若存在无法安全归属到本次更新的未提交改动，列出文件并要求开发者确认提交范围；不要自动纳入。此时不写入文件、不提交、不推送、不编辑 PR。

## 草案与批准门禁

基于真实 diff 和真实 PR 状态生成完整草案，至少包含：

- 一个符合开发者所选语言的 PR 标题；
- 结构化 PR 摘要，至少包含变更内容、影响范围、验证情况和风险/未验证项；
- 目标状态（保持、`open` 或 `draft`）；
- 如果开发者选择更新 Changelog，则对应的中文 Changelog 条目草案；
- 计划显式暂存的文件列表、验证信息和风险。

Changelog 草案必须延续现有 `CHANGELOG.md` 的版本标题和分类小节格式；版本号无法从受影响工程设置与分支变更一致确定时，询问开发者，不猜测或创建不确定的版本标题。

在聊天中完整展示草案并明确请求审核。开发者未批准前保持只读，不修改 `CHANGELOG.md`、不暂存、不提交、不推送、不编辑 PR。批准必须一次性覆盖草案中的全部拟议修改。

## 批准后的操作

开发者明确批准后，按以下顺序操作：

1. 如已批准更新 Changelog，将已审核的中文条目写入 `CHANGELOG.md`。
2. 使用 `$git-commit` skill 检查完整差异、仅显式暂存开发者确认的文件、排除无关改动与敏感信息，并创建适当的中文 Conventional Commit。
3. 验证提交结果后，普通推送目标 PR 的 head 分支；不强推。
4. 使用 `gh pr edit` 更新 PR 标题与正文。
5. 按需使用 `gh pr ready` 将草稿转为 `open`，或使用 `gh pr ready --undo` 将 `open` 转为草稿。
6. 重新读取 PR 并返回 PR URL、提交信息与最终状态。

不得在批准前写入 Changelog、提交、推送或编辑 PR。不得自动拉取、变基、强推、合并、解决冲突、关闭或重开 PR，也不得回滚已完成的 Git 操作。

## 失败边界

- `gh` 未安装、未认证、远端不是 GitHub、PR 无法读取、当前分支游离、目标不唯一或没有可归属的变更时，停止且不写入。
- Changelog 写入或 Git 提交失败：停止；不推送也不编辑 PR。
- 推送失败：停止；不编辑 PR。报告已创建的本地提交和推送错误。
- 编辑 PR 标题/摘要或转换状态失败：不回滚已完成的本地提交或推送；重新读取 PR 并报告当前状态和 GitHub 错误，不自动重试失败的写操作。
- 任何需要开发者决策的歧义（目标 PR、提交范围、版本号、认证/权限修复）都应停止并询问，不自行扩大操作范围。

不要记录、持久化或在回复中暴露 token、cookie、账号标识、认证载荷或完整私有响应。
